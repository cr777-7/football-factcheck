# 首次使用引导：由 AI 帮用户完成配置

## 先检查，避免每次重问

激活 Skill 后先运行 `python3 <skill-dir>/scripts/setup.py status`。默认读取技能目录的 `config.json` 及其同目录存在的 `.env`；系统环境变量优先。用户指定外部配置时，对 status/test/parallel_check 始终传入同一组 `--config`、`--env-file` 参数，不另建重复配置。外部配置默认只读取它同目录的 `.env`，不会借用技能安装目录的 Key。

status 只报告密钥是否存在，不显示密钥。不要读取并展示 `.env`，不要搜索用户其他项目或目录中的凭证。缺配置返回 `needs_configuration`；缺 Key 返回 `needs_credentials`；仅一模型返回 `single_model_only`；至少两模型且有 Key 返回 `ready_to_test`。这是离线状态，不是接口验收。

## 缺服务商和模型时

一次问清最少的信息，示例：“你准备用哪家模型 API 服务？告诉我服务名称或官方文档链接即可；已有网关的话也可提供地址。Key 请留在本地，不用发给我。”

- 用户不了解网关时解释：它是访问模型的服务地址；一个支持多模型的兼容网关通常只需一个 Key。也可以分别配置多个兼容服务。
- 若用户还没有服务，协助查看其考虑的服务商官方接入文档、计费和模型目录，说明可选路径；由用户自行注册、开通和申请 Key。不要替用户购买，不随意选陌生网关来接收凭证。
- 在用户选定的服务商官方文档或控制台信息中核对：是否支持 Chat Completions 协议、完整请求地址、可用模型的准确 ID、认证方式和当前参数要求。记录已看的文档链接供用户核对；不根据显示名称猜 ID，也不把基础地址直接当完整请求地址。
- 默认目标是至少两种不同模型家族，条件允许时配置 DeepSeek / Claude / Gemini / GPT 四类。未开通的模型不硬填；不要将原生 Messages 或 generateContent 地址交给兼容脚本。
- 无法访问文档时请用户提供接口/模型列表的非敏感部分。缺少这些必要信息时保留进度，继续可做的公开来源核查，不伪造配置已完成。

确认信息后 AI 直接创建非密钥配置。对于同一网关可运行：

```
python3 <skill-dir>/scripts/setup.py init --endpoint "完整HTTPS接口地址" --model "deepseek=实际模型ID" --model "gpt=实际模型ID"
```

上面中文均需替换成实际值。`init` 不会覆盖已有配置。多服务或修改现有配置时，AI 可按 config.example.json 的结构直接编辑非密钥配置，各服务用不同 `api_key_env`，保留无关配置与用户自选模型；然后运行 status 检查。不要自动禁用失败模型来伪装全部成功。

## 用户在本地填 Key

AI 填好网关和模型信息后，只把最后的 Key 填写交给用户。优先给可点击的本机文件路径或以下隐藏输入方式，而不是要求用户把 Key 发进聊天。

用户可在**自己的终端**运行：

```
python3 <skill-dir>/scripts/setup.py key
```

输入不回显；写入技能目录 `.env`，保留其他变量；POSIX 下文件权限为 600。AI 不要代为在可记录输入的工具里粘贴密钥。多个服务时使用 `key --name DEEPSEEK_API_KEY` 等与配置一致的变量名；外部文件加 `--env-file /path/to/.env`。也可让用户在本地编辑器复制 `.env.example` 为 `.env` 后填写，或通过其自己的密钥管理工具注入环境变量。

Key 不放在脚本、config.json、命令参数、报告、GitHub issue 或仓库中。脚本不负责生成/申请 Key。用户填好后继续 status；不要仅因用户说已填就宣称接口已通。

## 连接测试与交付

首次配置完成或更换服务/模型/Key 后，告诉用户“将对每个已配置模型发送一条测试内容，可能产生少量 API 费用”，随后在用户已要求接入测试的授权范围内运行：

```
python3 <skill-dir>/scripts/setup.py test
```

每模型最多一条请求，无自动重试；使用内置预测性测试句，不发送用户稿件。核验鉴权、实际接口响应、JSON 和断言 ID 覆盖，不对足球知识准确率作验收。输出逐模型成功/失败与排查建议，不输出返回正文或 Key。

- 全部通过且至少两模型：`ready`，说明完成数量，接着处理用户原本要核查的内容。
- 至少两模型通过但有失败：`partial`，列出成功和失败模型；可继续用成功结果核查，明确覆盖局限。
- 仅一模型通过：`single_model_only`，不能称为多模型交叉核查。协助排查其他模型，或明确降级为单模型加网页验证。
- 都失败：`not_ready`；按具体错误处理，不重复无意义测试。

典型排查：401 检查 Key/环境变量覆盖；403 检查权限；404 检查接口与模型；429 查限流/额度；400 核对参数兼容；网络错误查 DNS/TLS；输出格式失败查模型 JSON 能力；输出截断调整合适的上限再测。没有更改或新证据时不反复请求。

脚本拒绝跨网关重复的模型 ID，返回模型标识重复或冲突时保守降低独立模型数；不同别名和同一网关背后的真实模型身份仍无法由脚本独立证明。Key 存在、连接通过、多模型审阅通过、网页证据已核验是不同状态。

## 后续复用

`parallel_check.py` 默认复用技能目录 `config.json` 和已存在的 `.env`，不要求每次重新填写。外部配置继续显式传路径。配置未变时无需每次另做付费连接测试，直接核查即可；接口运行失败再按错误排查。不要把先前测试通过当作永久可用的保证。

若宿主不支持本地脚本/文件或用户尚未安装 Skill，先说明需要这些能力；只把文档上传到普通聊天并不保证能永久安装和读取本地密钥。不能执行时交付本地运行步骤，不声称代为完成。
