# football-factcheck · 足球信息核查 Skill

通过多个模型独立审阅和宿主助手联网查证，核查足球文字、球员介绍、比赛数据、新闻、转会消息及 HTML 球星画报。支持中文及其他语言；不把模型多数意见当作事实证据。

## 安装

需要 Python 3.9+，以及能读取 Skill、执行脚本和浏览网页的助手环境。

将本仓库文件夹命名为 `football-factcheck`，复制到：

- Codex：`~/.codex/skills/football-factcheck/`
- Claude Code：`~/.claude/skills/football-factcheck/`
- 其他支持 SKILL.md 的宿主：使用该宿主规定的技能目录。脚本跨平台，宿主发现机制需自行验证。

重新打开会话后，在 Codex 中输入：

```
$football-factcheck 请核查：阿根廷赢得2022年男子世界杯冠军。
```

也可以直接说：“帮我核查这篇足球文章，列出事实错误、来源和修正建议。”识别方式取决于宿主。Codex UI 元数据已提供，其他宿主的斜杠命令不作可用性保证。

## 配置模型

首次调用时，AI 会先检查配置并引导你完成以下步骤：

1. 告诉 AI 你使用的模型 API 服务名称或官方文档链接，不用提供 Key。
2. AI 核对该服务的兼容接口、可用模型 ID，并填写非密钥配置。建议至少接入两种不同模型家族。
3. 你在本地填入自己申请的 Key。可在自己的终端运行 `python3 scripts/setup.py key` 隐藏输入，也可编辑本地 `.env` 或设置环境变量。
4. AI 发送每模型一条测试内容（可能产生少量 API 费用），列出成功模型和失败原因，然后继续核查任务。

之后自动复用配置，无需每次填写。支持 Chat Completions 兼容接口；原生 Claude/Gemini 接口需兼容网关。AI 不会代替你注册购买服务、生成 Key，或猜测模型 ID。宿主需要执行脚本和访问本地文件的能力；仅上传文档到普通聊天不保证能够完成安装与配置。

详细流程见 [首次使用引导](references/onboarding.md)，参数说明见 [配置说明](references/configuration.md)。手动使用也可以复制配置模板后填写。

无密钥仍可由宿主进行公开来源核查，但必须说明未执行多模型审阅。

## 使用示例

- “核查这篇球星介绍，给出每个数字的来源。”
- “截至2024年6月，这个球员的球队和球衣号码是否正确？”
- “这条转会消息是已经官宣、媒体报道，还是没有依据？”
- “检查 player.html，先给报告。”
- “按已核实的报告另存修正版 HTML，并生成 Excel。”

脚本可独立提取 HTML、并行请求模型、导出报告。网页搜索和最终证据裁决由宿主助手完成。完整流程见 [SKILL.md](SKILL.md)。

## 报告

每项包含：原断言、错误/瑕疵/正确/证据不足/非事实判断、判定理由、建议表述、实际核验的来源、模型分歧和适用时间。默认回复或 Markdown，可选 Excel（`python3 -m pip install -r requirements.txt`）。

用户明确要求修正时才修改原文，并保留备份、重新提取核对。无法验证的内容不会标为正确。
